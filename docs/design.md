# AI가 만든 HTML을 고치는 편집기 설계

## 요청

> 아 이제 곧 HTML시대가 될거같은데 프레젠테이션을 HTML로 바꾸는거라던가, 아님 완성된 HTML 을 쉽게 편집할수있는 툴같은거 만들면 잘되려나?

> /brainstorming AI대상은 아닌데 내가 생각하는건

> 생성AI가 뽑아준 HTML을 바꾸는거라고 이제는 진짜 처음부터 자료 만들지 않는 시대니까

## 결정사항

- 제품의 중심: 생성 AI가 만든 HTML을 사람이 고치는 도구. AI는 HTML을 만드는 쪽이고, 도구를 쓰는 것은 사람이다.
- 전제: 발표·설명 자료가 PDF·PPT에서 인터랙션 있는 웹 페이지로 옮겨 간다. 자료는 AI가 초안을 만들고 사람이 마무리한다.
- 쓰임: 회사 발표·영업, 수업·연수, 병원 같은 곳의 1대1 상담. 특정 분야로 좁히지 않는다. 첫 기능과 첫 사용자가 흐려지는 점은 감수한다.
- 조작하는 사람: 발표자나 상담하는 사람이 자기 화면에서 조작한다. 청중이 자기 기기로 여는 경우는 범위 밖이다.
- 고친 뒤: 그 자리에서 띄우기, 파일로 저장. 링크 공유·로그인·PDF/PPT 내보내기·결제는 범위 밖이다.
- 호스팅: 정적 호스팅(GitHub Pages)만 쓴다. 서버 처리는 없고 모든 처리는 브라우저 안에서 한다.
- 성공 기준
  1. 첫째: 내가 직접 쓴다. AI가 만든 내 실제 자료 3건을 바깥 코드 편집기 없이 이 도구로 고쳐서 쓴다.
  2. 둘째(약함): 남이 쓴다, 포트폴리오로 보여 줄 수 있다.
  3. 돈은 기준이 아니다.
- 맞출 사람: 처음 버전은 나(코드를 아는 사람)에게 맞춘다. 코드 창을 둔다. 코드를 모르는 사람용 쉬운 화면은 다음 버전이다.
- 만들 곳: 새 저장소. 주소는 `j-paku.github.io/` 아래 저장소 이름. J-paku의 검사 규칙과는 분리한다.
- 기술: React·TypeScript·Next.js 정적 내보내기(`output: 'export'`, `basePath`는 저장소 이름). 도구 자체의 스타일은 CSS Modules로 쓰고 Tailwind는 쓰지 않는다.
- Tailwind를 쓴 입력 HTML: AI가 만든 HTML이 Tailwind CDN을 쓰면, 색·크기를 Tailwind 클래스 자체를 바꿔서 고친다. 처음 버전에 넣는다. 도구 자체의 스타일(CSS Modules)과는 별개의 이야기다.
- 받을 HTML: HTML 한 파일, 그리고 CSS·이미지가 따로인 여러 파일 폴더. 글자가 HTML 안에 있는 요소는 클릭으로 고치고, 스크립트가 그린 요소는 코드 창에서 고친다.
- 브라우저: 크롬 계열(Chrome·Edge)만. 폴더를 열고 원래 자리에 저장하는 기능(File System Access API)이 크롬 계열에만 있기 때문이다.
- 꼭 할 일
  - 클릭 편집: 글자 고치기, 이미지 바꾸기, 색·크기 바꾸기, 지우기·복제·순서 바꾸기
  - 코드 창, 그 자리에서 띄우기, 파일로 저장
- 막을 실패: 저장하면 원본 모양이 바뀜, 저장 안 하고 닫힘, 밖에서 파일이 바뀜, 잘못 고침(되돌리기).
- 나누기: 조각으로 나누지 않고 스펙 하나로 전부 설계한다. 처음 써 보는 날이 늦어지는 점은 감수한다.

## 접근안 (선택됨)

**원본 텍스트가 정본.** 클릭 편집이든 코드 편집이든 전부 원본 글자 일부를 바꾸는 변경으로 처리한다.

고른 이유: 「원본 모양 유지」「인터랙션 유지」「되돌리기」를 셋 다 만족하는 유일한 안이다.

고르지 않은 안

| 안 | 고르지 않은 이유 |
|---|---|
| 화면이 정본, 저장 때 차이를 반영 | 스크립트가 바꾼 상태(지금 슬라이드 번호 등)가 차이로 잡혀 저장될 위험이 있다. 차이 반영이 틀리면 원본이 깨진다 |
| 기존 편집기 라이브러리(GrapesJS 등) | 자기 형식으로 HTML·CSS를 다시 써서 원본 모양이 바뀌고, 스크립트 인터랙션이 깨지기 쉽다. 꼭 막기로 한 실패를 못 막는다 |

## 설계 개요

### 목적

AI가 만든 HTML(한 파일 또는 폴더)을 브라우저에서 열고, 클릭과 코드 창으로 고치고, 원본 모양을 지킨 채 원래 파일에 저장하고, 그 자리에서 띄우는 정적 웹 도구.

### 구조

- 화면은 세 덩어리다.
  - 편집기 화면: 파일 목록, 코드 창, 속성 패널, 도구 막대
  - 미리 보기: `iframe`. 원본에 표식을 넣은 사본을 실행한다. 스크립트와 인터랙션은 그대로 동작한다
  - 파일 공급: `srcdoc`. 미리 보기 `iframe`은 `sandbox="allow-scripts"`(`allow-same-origin` 없음)로 격리하고, 시작 HTML이 참조하는 CSS·이미지·스크립트(CSS 안 `url()`·`@import` 포함)를 열어 둔 폴더 내용에서 꺼내 `data:` URL로 바꿔 넣은 문서를 `srcdoc`으로 준다. 참조한 파일이 열어 둔 폴더 안에 다 있을 때만 네트워크 요청이 없다(바꾸지 못한 참조는 위험 1의 한계. 2026-10-18 수정). 2026-10-18 실측으로 변경(처음 안은 Service Worker였으나 격리한 `iframe`의 요청을 받지 못했다. 위험 1)
- 정본은 파일마다 원본 텍스트 하나뿐이다. 파일마다 CodeMirror 문서 상태를 메모리에 둔다.
- 미리 보기에는 편집 모드와 조작 모드가 있다.
  - 편집 모드: 클릭하면 요소가 선택된다
  - 조작 모드: 클릭하면 원래 인터랙션(다음 슬라이드, 탭 열기)이 실행된다
  - 예: 조작 모드로 3번 슬라이드까지 넘긴 뒤 편집 모드로 바꿔서 고친다

### 부품

각 부품은 한 가지 일만 하고, 정해진 입력과 출력으로만 다른 부품과 통한다.

| # | 부품 | 자리 | 하는 일 |
|---|---|---|---|
| 1 | 원본 위치 표 | `utils/` | HTML·CSS 텍스트를 받아 요소·텍스트·속성·CSS 규칙·선언마다 원본 범위(시작·끝 위치)를 돌려준다. `parse5`(`sourceCodeLocationInfo`)와 `postcss`를 쓴다. 순수 함수 |
| 2 | 미리 보기 사본 만들기 | `utils/` | 원본과 위치 표를 받아, 원본 위치가 있는 요소마다 표식 속성을 넣고 선택 감지 스크립트를 넣은 사본 텍스트를 돌려준다. 순수 함수 |
| 3 | 편집 명령 | `utils/` | 글자 바꾸기·이미지 교체·색과 크기·지우기·복제·순서 바꾸기 명령과 위치 표를 받아, 원본의 어디부터 어디까지를 무엇으로 바꿀지 목록을 돌려준다. 순수 함수 |
| 4 | 미리 보기 연결 | `iframe` 안 스크립트 + 편집기 쪽 수신 | 클릭한 요소의 표식, 적용된 CSS 규칙 후보, 계산된 색·크기를 편집기로 보낸다. 편집기는 강조 표시·글자 편집 시작과 끝을 미리 보기로 보낸다 |
| 5 | 파일 접근 | `lib/` | 폴더·파일 열기, 읽기, 쓰기, 지문 읽기, `IndexedDB` 임시 보관. 앱 밖과 통하는 곳은 여기 한 곳뿐이다 |
| 6 | 파일 공급 | `utils/`(`src/utils/preview-build-srcdoc.ts`) | 열어 둔 파일들과 시작 HTML 경로를 받아, 시작 HTML의 참조(CSS·이미지·스크립트·CSS 안 `url()`·`@import`)를 그 파일의 `data:` URL로 바꾼 `srcdoc` 텍스트를 돌려준다. HTML·CSS 파일은 넣기 전에 같은 방식으로 바꾸므로 몇 단계 깊이의 참조든 통한다. 앱 밖과 통하는 입구가 없는 순수 함수. 2026-10-18 실측으로 변경(처음 안은 `public/`의 Service Worker) |
| 7 | 화면 부품 | `components/` | 파일 목록, 코드 창(CodeMirror 6), 속성 패널, 도구 막대, 띄우기 화면 |
| 8 | Tailwind 클래스 판정 | `utils/` | `class` 속성의 클래스 이름들을 받아, 글자 색·배경색·글자 크기를 정하는 클래스와 그 값을 돌려준다. 새 값을 받으면 바꿔 넣을 클래스 이름을 만든다. 순수 함수 |

색·크기를 고칠 때는 두 가지 중 고르게 한다.

- 「이 규칙 고치기」: 적용된 CSS 규칙의 원본 선언을 고친다. 같은 규칙을 쓰는 다른 요소도 같이 바뀐다
- 「이 요소에만」: 그 요소에 `style` 속성을 붙이거나 고친다
- 「Tailwind 클래스 바꾸기」: 입력 HTML이 Tailwind CDN을 읽고 있고, 그 요소의 색·크기가 Tailwind 클래스로 정해져 있을 때만 나온다. 이때는 이 선택지가 기본이다

Tailwind 클래스 바꾸기의 범위는 이렇다.

- 대상 속성: 글자 색(`text-blue-500`), 배경색(`bg-red-100`), 글자 크기(`text-lg`)
- 기본 팔레트와 글자 크기 단계에서 고른다. 팔레트에 없는 색을 고르면 `text-[#1a2b3c]` 같은 임의 값 클래스로 넣는다
- `class` 속성의 원본 범위 안에서 그 클래스 이름 하나만 바꾼다. 다른 클래스와 공백은 건드리지 않는다
- Tailwind CDN은 화면의 클래스가 바뀌면 CSS를 다시 만드는 것으로 보므로(확인 전 추정. 뼈대 단계에서 잴 예정이었으나 1단계에서는 재지 않았고, 5단계(색·크기 바꾸기)로 옮겼다. 2026-10-18 수정), 미리 보기는 다시 불러오지 않고 바로 바뀐다
- `hover:`·`md:`·`dark:` 같은 접두사가 붙은 클래스는 바꾸지 않고 그대로 둔다. 속성 패널에 그런 클래스가 있다고만 알린다
- 설정(`tailwind.config`)으로 만든 색 이름은 팔레트에 나오지 않는다. 클래스 이름을 직접 입력하는 칸으로 바꾼다

이미지를 바꿀 때 새 이미지는 이렇게 넣는다.

- 폴더로 열었으면 새 이미지를 폴더에 복사하고 `src`를 상대 경로로 바꾼다
- 파일 하나로 열었으면 폴더에 쓸 권한이 없으므로 새 이미지를 data URL로 `src`에 넣는다

### 데이터 흐름

1. 열기: 폴더나 파일을 고른다. 파일을 읽어 원본 텍스트와 읽은 시점의 지문(수정 시각·크기)을 저장한다. 원본 위치 표를 만들고, 표식을 넣은 사본을 미리 보기에 띄운다. 띄울 때는 사본이 참조하는 폴더 안 파일을 `data:` URL로 바꿔 넣은 `srcdoc`을 격리한 `iframe`에 준다. 2026-10-18 실측으로 변경(처음 안은 Service Worker가 미리 보기의 요청마다 파일을 꺼내 주는 방식).
2. 클릭 편집: 편집 모드에서 요소를 클릭하면 미리 보기가 그 표식을 편집기로 보낸다. 편집기는 원본 범위를 찾아 코드 창의 그 줄을 강조하고 속성 패널을 연다. 글자를 입력하거나 색을 고르면, 편집 명령이 바꿀 곳 목록을 만들어 CodeMirror 변경으로 넣는다. 그 뒤 위치 표를 다시 만들고 미리 보기를 갱신한다.
3. 코드 편집: 코드 창에서 직접 고쳐도 같은 길을 탄다. 입력이 멈추고 잠시 뒤 미리 보기를 갱신한다.
4. 미리 보기 갱신
   - 글자·속성·CSS 변경: 다시 불러오지 않고 미리 보기 화면에 바로 넣는다. 보던 슬라이드가 유지된다
   - 지우기·복제·순서 바꾸기: 다시 불러오고 스크롤 위치를 되돌린다
5. 저장: 디스크에 있는 지금 파일의 지문을 연 시점의 지문과 비교한다. 같으면 원본 텍스트를 그대로 쓰고 지문을 갱신한다. 다르면 실패 대응으로 간다.
6. 띄우기: 표식이 없는 원본 그대로를 전체 화면으로 띄운다.

### 실패 대응

| 상황 | 대응 |
|---|---|
| 저장하면 원본 모양이 바뀜 | 저장은 늘 원본 텍스트를 그대로 쓴다. 화면을 다시 HTML로 바꿔 쓰는 일은 없다. 입력한 글자에 `&`·`<`가 있으면 그 부분만 `&amp;`·`&lt;`로 바꾼다. 글자 앞뒤의 줄바꿈과 들여쓰기는 건드리지 않는다 |
| 저장 안 하고 닫힘 | 닫을 때 브라우저 경고를 띄운다. 고칠 때마다 `IndexedDB`에 파일 경로·연 시점 지문·지금 텍스트를 임시 보관한다. 다시 열면 복원할지 묻는다 |
| 밖에서 파일이 바뀜 | 저장 직전 지문이 다르면 셋 중 하나를 고르게 한다. 내 것으로 덮어쓰기, 디스크 것 불러오기(내 변경은 버림), 취소. 두 내용을 합치는 기능은 없다 |
| 잘못 고침 | 클릭 편집과 코드 편집이 같은 CodeMirror 되돌리기 기록을 쓴다. 기록은 파일마다 따로다 |
| 클릭으로 못 고치는 요소 | 스크립트가 만든 요소와, 깨진 HTML을 브라우저가 채워 넣은 요소는 원본 위치가 없다. 클릭하면 「코드 창에서 고쳐 주세요」라고 안내한다 |
| 서식이 섞인 글자 | 글자 고치기는 글자 덩어리 하나씩이다. 굵게·기울임 같은 서식 바꾸기는 코드 창에서 한다 |
| 크롬 계열이 아님 | 시작 화면에서 크롬이나 엣지로 열라고 안내한다 |
| 쓰기 권한이 풀림 | 저장할 때 권한을 다시 요청한다 |

### 테스트

- 단위(vitest): 원본 위치 표, 미리 보기 사본 만들기, 편집 명령, Tailwind 클래스 판정. HTML과 편집 명령을 넣고 결과 텍스트를 비교한다. 모든 경우에 공통으로 「바꾼 범위 밖의 글자는 한 글자도 안 바뀜」을 확인한다.
- 표본: 손으로 만든 HTML만 쓰지 않는다. Claude·ChatGPT·Gemini가 실제로 만든 HTML을 10개쯤 모아서 쓴다. 한 파일, 폴더, Tailwind CDN, 스크립트가 그리는 것을 섞는다.
- 브라우저 통합(Playwright): 실제 브라우저에서 클릭·입력·되돌리기·저장·덮어쓰기 경고·Tailwind 클래스 바꾸기를 확인한다. Tailwind CDN 스크립트는 테스트에서 로컬 사본으로 바꿔 끼워 네트워크에 기대지 않는다. 폴더 고르는 창은 자동 테스트가 누를 수 없으므로, 테스트에서는 브라우저 안의 저장 폴더(OPFS)를 열린 폴더 대신 쓴다. 같은 `FileSystemDirectoryHandle`로 다룰 수 있다.
- 손 확인: 성공 기준 그대로. 내 실제 AI 자료 3건을 바깥 코드 편집기 없이 이 도구로 고쳐서 쓴다.
- 배포: GitHub Actions에서 타입 검사·린트·단위·통합 테스트를 통과하면 GitHub Pages에 배포한다.

### 위험

1. 미리 보기 격리: AI HTML의 스크립트가 편집기와 같은 출처에서 돌면, 편집기의 임시 보관과 폴더 권한에 손댈 수 있다. GitHub Pages는 `j-paku.github.io` 아래 모든 저장소가 같은 출처라서 포트폴리오 사이트와도 겹친다. 2026-10-18 실측으로 변경(Chromium headless에서 잰 결과로 방식을 정했다).
   - 격리하지 않은 같은 출처 `iframe`에서는 AI HTML의 스크립트가 편집기의 `IndexedDB`와 DOM을 읽을 수 있었다. 위험은 실제로 있다.
   - Service Worker는 `sandbox="allow-scripts"`(`allow-same-origin` 없음) `iframe`의 문서와 하위 요청을 받지 못했다. 전부 네트워크로 갔다.
   - 부모(편집기)가 만든 `blob:` URL은 불투명 출처 `iframe`에서 읽히지 않았다.
   - 격리를 지키며 동작한 방식은 하나였다. `sandbox="allow-scripts"` `iframe` + `srcdoc`이고, 시작 HTML의 참조(CSS·이미지·스크립트·CSS 안 `url()`·`@import`)를 `data:` URL로 바꿔 넣는다. 8MB 이미지도 열렸고 네트워크 요청은 0건이었다(참조한 파일이 다 폴더 안에 있던 측정이다. 바꾸지 못한 참조는 아래 한계. 2026-10-18 수정). 그래서 이 방식으로 정했다(부품 6).
   - 이 방식의 한계
     - 실행 중에 만드는 상대 참조(`fetch`·XHR·module 안의 상대 `import`·`img.src` 대입·Worker)는 안 된다.
     - 폴더 안 다른 페이지로 가는 `<a href>`(예: `about.html`)를 눌러도 그 페이지로 가지 않는다. `a`·`area`의 `href`는 바꾸지 않으므로 아래 항목처럼 편집기 주소로 풀린다. 2026-10-18 추가
     - 바꾸지 못한 상대 참조(폴더에 없는 파일, 그리고 파일 하나로 열었을 때의 상대 참조 전부)는 편집기 주소(`/html-editor/...`)를 기준으로 풀려서 그 주소로 요청된다. 2026-10-18 추가
     - 불투명 출처라서 AI HTML의 `localStorage`·`IndexedDB`·쿠키는 SecurityError가 난다.
     - `alert`·form 제출·새 창은 막힌다(`sandbox`에 `allow-modals`·`allow-forms`·`allow-popups`가 없다).
     - HTML을 글자 단위로 훑어서 바꾸므로 일부 엔티티(`&amp;` 말고는 풀지 않는다)·`<base href>`·쉼표만 있는 `srcset`·CSS 이스케이프·SRI는 처리하지 않는다. 2단계에서 `parse5` 위치 표(부품 1)가 들어오면 바꿀 수 있다.
2. Tailwind CDN을 쓴 입력 HTML: 색이 `text-blue-500` 같은 클래스로 정해져서 원본에 CSS 규칙이 없으므로 클래스 자체를 바꾼다. Tailwind CDN에는 v3(`cdn.tailwindcss.com`)와 v4(`@tailwindcss/browser`)가 있고, 클래스 이름 판정은 두 판 모두에 통하는 기본 이름만 다룬다. 두 판의 차이로 판정이 틀리는 경우가 있을 수 있다(확인 전 추정). 표본에 두 판을 모두 넣어 확인한다.
3. CSS 규칙 찾기: 미디어 쿼리, `!important`, 상속, CSS 변수로 정해진 색은 원본의 어디를 고쳐야 할지 애매하다. 후보 규칙을 보여 주고 고르게 한다.
4. 인터랙션 상태: 지우기·복제·순서 바꾸기 뒤에 다시 불러오면 보던 슬라이드가 처음으로 돌아갈 수 있다.
5. 크롬 계열에서만 동작한다.
6. 범위가 크다: 한 번에 전부 설계했기 때문에 처음 써 보는 날이 늦다.
